# План испытаний на OpenWrt

Статус: локальные shell-проверки выполнены; испытания реального роутера, компьютера и телефона **ещё не выполнены**. Не отмечайте пункт пройденным без наблюдаемого результата.

## Подготовка

- Запасной роутер, модель/версия прошивки, схема DSA/swconfig/VLAN, резервная копия вне роутера, Ethernet и известный способ failsafe.
- Доступ по SSH с компьютера и телефона. Пароль вводить только в SSH-клиенте. Использовать UTF-8 и ANSI; проверить ширину 40/60/80 колонок.
- Зафиксировать вывод `ubus call system board`, `ip link` и `uci show network`; перед передачей другим людям скрыть адреса и имена. **Не передавать `uci show wireless`/PPPoE без удаления паролей.**
- Проверить свободное место, наличие `uci`, `ubus`, `jsonfilter`, `nohup`, `ip`; установить проект.

## Последовательность

1. `owp demo`: убедиться, что вымышленные данные подписаны. Запустить `owp`, выбрать RU, выйти, повторить: язык сохранился. Переключить EN. `0` возвращает назад.
2. `owp status`, `clients`, `interfaces`: сравнить модель, RAM, IP, Wi-Fi состояние и реальные станции с LuCI. Выключенный клиент может оставаться в DHCP-арендах — это ожидаемо.
3. `owp doctor`: нормальная сеть; затем отдельно отсоединённый WAN-кабель, отказ DNS и недоступный VPN. Убедиться, что диагноз не выдаёт ICMP-фильтрацию за доказанный обрыв. Сканировать только свою LAN.
4. Создать малорисковую DHCP-привязку текущей аренды. Ввести `yes` — ничего не применится. Ввести `Yes`, **не подтверждать**: через 120 секунд файлы вернутся. Проверить логи транзакции.
5. Повторить изменение, подтвердить через второй SSH-сеанс командой `owp confirm`, введя `Yes`. После 120 секунд оно сохраняется. Проверить, что DHCP-резервация не создаётся повторно.
6. С проводного сеанса выключить Wi-Fi и дождаться автоматического возврата. Затем повторить, подтвердить по проводу, проверить сохранение. Включить обратно и подтвердить. Проверить смену SSID/пароля с телефоном: заново подключиться, проверить, подтвердить.
7. На отдельной тестовой станции выполнить временный ban. Проверить восстановление через 60 секунд. Не использовать единственный управляющий клиент.
8. Для поддерживаемого VPN: остановить сервис на 120 секунд, наблюдать восстановление. Отдельно проверить сценарий со сторонним kill switch; фиксировать, если интернет без VPN остаётся заблокированным.
9. PPPoE проверять с тестовым сервером/провайдерскими реквизитами и проводным доступом. Должен использоваться прежний WAN-порт и firewall-зона. Проверить IPv4, DNS, NAT и отдельно IPv6.
10. WAN перенос: только поддерживаемая простая DSA-схема. Оставить компьютер на другом LAN-порту. Выбрать тестовый LAN, переставить кабель WAN, проверить LAN-isolation/NAT/DHCP и подтвердить. Повторить без подтверждения — исходная схема восстанавливается, кабель вернуть вручную.
11. Отдельно проверить отказ на swconfig, tagged WAN, VLAN-filtered bridge, последнем LAN-порту, занятых портах и незакоммиченном UCI. Не обходить отказ на основной сети.
12. На запасном устройстве запустить изменение и перезагрузить до подтверждения. До старта сети должна восстановиться исходная конфигурация. Это единственное испытание плана, требующее намеренной перезагрузки; выполнить вручную.
13. Пакеты: проверить установленный manager (apk/opkg), список и установку небольшого известного пакета при достаточном flash. Проверить отказ на строках с пробелами/опциями. Пароль root менять вручную с запасным открытым SSH-сеансом.

Сохранять результаты с моделью, версией OpenWrt, коммитом проекта, PASS/FAIL и наблюдением. Не публиковать резервные копии и секреты в Issues.

## Восстановление

- После потери SSH подождать минимум 120 секунд плюс время перезапуска служб, затем переподключиться по прежним параметрам.
- При доступе по проводу: `owp rollback` → `Yes`.
- Резервные файлы и логи — `/etc/owrt-pocket/transactions/<id>/`. Не удалять текущую транзакцию.
- Если скрипт не работает, применить сохранённую вне устройства резервную копию через штатный LuCI/failsafe для своей модели. При поломке накопителя конфигурационный watchdog не поможет.
