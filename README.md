# OWRT Pocket

Цветной карманный помощник для OpenWrt в SSH-терминале. **Версия 0.2.0 — для испытаний на запасном роутере.** Языки: русский / English. Команда: `owp`.

Проект не требует Python, Bash, веб-сервера или доступа к облаку на роутере. Основа — `/bin/sh` (BusyBox ash), UCI, ubus, jsonfilter и штатные инструменты OpenWrt. Подходит для телефонного SSH-клиента с UTF-8 и ANSI-цветами. `NO_COLOR=1 owp` отключает цвета.

## Установка

Подключитесь к **своему** роутеру по SSH, например `ssh root@192.168.1.1`. Сохраните резервную копию через LuCI → System → Backup и скачайте её на компьютер. Первое испытание проводите при наличии проводного доступа.

**Скопируйте одну команду и выполните её в SSH-терминале роутера:**

```sh
wget -O /tmp/owrt-pocket-install.sh https://raw.githubusercontent.com/dagmagnat/owrt-pocket/main/install.sh && sh /tmp/owrt-pocket-install.sh
```

Роутер сам скачает меню с GitHub, проверит SHA-256 и установит его. Архив и
передача файлов с компьютера не нужны. Дождитесь сообщения **«Установлено!»**.
После этого открыть меню можно из любой папки:

```sh
owp
```

Нужен доступ роутера к интернету по HTTPS. Если скачивание не удалось, проверьте
интернет, DNS, дату роутера и сертификаты. Не используйте `--no-check-certificate`.
При отсутствии `wget`, но наличии `curl`:

```sh
curl -fL -o /tmp/owrt-pocket-install.sh https://raw.githubusercontent.com/dagmagnat/owrt-pocket/main/install.sh && sh /tmp/owrt-pocket-install.sh
```

Установщик открыт для проверки: [install.sh](install.sh). Он скачивает только
файл меню закреплённой версии 0.2.0 с проверкой SHA-256, без сборочных файлов
и прошивок. Та же команда подходит для повторной установки; выбранный язык
и настройки сохраняются. При ожидающем сетевом изменении установка остановится
до `owp confirm` или `owp rollback`.

Для установки без интернета передайте полный проект через SCP/SFTP,
распакуйте и выполните в его папке `sh install.sh --local`.

Установщик проверяет зависимости и устанавливает `/usr/sbin/owp` и загрузочное восстановление `/etc/init.d/owrt-pocket`. Сеть при установке не меняется. Язык выбирается при первом запуске, сохраняется в `/etc/owrt-pocket/language`; смена — меню 9 → 1.

## Короткие команды

```sh
owp                 # Главное меню
owp status          # Модель, память, диски, адреса, Wi-Fi
owp clients         # DHCP-аренды, соседи, Wi-Fi станции
owp interfaces      # Сети, PPPoE, адреса и RX/TX
owp doctor          # Диагностика без изменения конфигурации
owp scan            # Подтверждаемая ICMP-проверка до 32 адресов LAN
owp internet        # DHCP / PPPoE / повторитель / LAN IP
owp repeater        # Мастер интернета через Wi-Fi
owp repeater-status # Результат DHCP/проверки подсетей
owp lan             # Смена локального IPv4 роутера (/24)
owp confirm         # Сохранить ожидающее изменение: ввести Yes
owp rollback        # Немедленно вернуть предыдущую конфигурацию: Yes
owp demo            # Пример интерфейса с вымышленными данными
```

Для демо на Linux/macOS без OpenWrt: `sh src/owp demo`. На Windows с Git Bash: `bash src/owp demo`.

## Меню

```text
━━ OWRT POCKET 0.2.0 ━━
OpenWrt
RAM: 68 / 256 MiB

1 Состояние роутера
2 Клиенты и привязки IP
3 Интерфейсы и трафик
4 Wi-Fi
5 Диагностика сети
6 Исправления и VPN
7 Интернет / повторитель / LAN IP
8 Пакеты
9 Настройки и подтверждение
0 Выход
```

Пример выше демонстрационный. В терминале состояния «ДА / ВКЛЮЧЁН» зелёные, «НЕТ / ВЫКЛЮЧЕН» красные, предупреждения жёлтые. На экранах выбора `0` возвращает назад; в главном меню выходит. Ввод данных не является меню: подсказки отмечают, где `0` отменяет ввод.

| Раздел | Возможности первой версии |
|---|---|
| Состояние | Модель и версия прошивки, uptime, load average, RAM, flash, IPv4/IPv6 маршруты, фактический Wi-Fi статус |
| Клиенты | DHCP, ARP/NDP-соседи, hostapd-клиенты, signal/bitrate при наличии `iw`; временный Wi-Fi ban на 60 секунд |
| Привязка IP | Резервирование **текущего DHCP IPv4** по MAC, отказ при существующей резервации |
| Интерфейсы | Все UCI-сети, включая созданные вручную и PPPoE; адреса, состояние и RX/TX счётчики |
| Wi-Fi | Включение/выключение радиомодулей, смена SSID и пароля существующего WPA2/WPA3 Personal AP |
| Диагностика | LAN и carrier портов, IPv4 маршрут, gateway, два внешних ICMP-адреса, локальный DNS, policy routes, VPN и последние сетевые логи |
| Сканирование | Только своя LAN IPv4 `/24`, блок до 32 адресов, с `Yes`; DHCP/ARP и Wi-Fi дают дополнительные сведения |
| Исправления | DNS/DHCP restart, WAN renew, остановка известного VPN-сервиса на 120 секунд; включение/отключение отдельных VPN-интерфейсов |
| Интернет | DHCP и PPPoE на существующем WAN, мастер AP+STA/NAT повторителя, смена LAN IP; перенос WAN-порта в простой DSA-схеме |
| Пакеты/сервисы | Просмотр, установка пакета из уже настроенных feeds, автоматический выбор `apk`/`opkg`, просмотр статуса init-сервисов |
| Настройки | Язык, штатный `passwd root`, подтверждение и откат |

`iw station dump` показывает радиопараметры, а не измеренную скорость интернета клиента. DHCP-аренда не означает, что устройство сейчас подключено. Скрипт не обещает точного общего числа онлайн-клиентов: проводные и спящие устройства нельзя надёжно посчитать по арендам.

## Как работает откат

1. Скрипт отказывается перезаписывать незакоммиченные UCI-изменения. Подготавливает отдельную копию четырёх файлов: `network`, `wireless`, `dhcp`, `firewall`.
2. Показывает действие и запрашивает **точно `Yes`**. `yes`, `YES`, `Y` и пустой ввод не подходят.
3. Отсоединённый от SSH процесс запускает watchdog **до** применения. Конфигурация меняется через 2 секунды; отсчёт отката — 120 секунд с запуска watchdog.
4. После проверки доступа выполните `owp confirm` и введите `Yes`. Это работает и из второго SSH-сеанса. Можно также выбрать 9 → 3 в исходном меню.
5. Без подтверждения предыдущие файлы восстанавливаются и сетевые службы перезагружаются. При перезагрузке роутера незавершённое изменение восстанавливается init-скриптом до обычного старта сети.

**При выключении единственного Wi-Fi доступа:** соединение пропадёт, и через примерно две минуты Wi-Fi вернётся. Чтобы оставить Wi-Fi выключенным, подтвердите по проводу или через другую доступную сеть. После смены Wi-Fi-пароля используйте новый пароль для переподключения до подтверждения.

Это конфигурационный откат, а не гарантия доступа при любой поломке. Не запускайте параллельно изменения в LuCI/UCI: скрипт блокирует собственные сеансы, но не сторонние редакторы; откат восстанавливает полные файлы и может затереть параллельные изменения. Повреждение накопителя, отсутствие питания или неисправный драйвер он не устраняет.

Пароль root, установка пакетов, DNS restart, WAN renew и временный ban клиента не входят в конфигурационный откат. Смена пароля root выполняется стандартной программой `passwd` с повторным вводом. Известные VPN-сервисы (`openvpn`, `sing-box`, `xray`, `tailscale`) восстанавливаются отдельным таймером через 120 секунд; автозагрузка не меняется. Это не полноценная поддержка всех VPN/policy routing: остановка сервиса может не убрать kill switch или правила сторонних пакетов. Удаление VPN не выполняется.

## WAN и PPPoE

В меню **7 → 2** задаются PPPoE-реквизиты; **7 → 3** переключает WAN на DHCP, удаляет сохранённые PPPoE-реквизиты и включает получение DNS автоматически. Эти операции используют существующий WAN-порт и его firewall-зону; работают и с существующим VLAN WAN на swconfig. Ограничение DSA ниже относится именно к **переносу физического WAN-порта**. Переключение на проводной DHCP/PPPoE отключает только созданный этим помощником Wi-Fi uplink, сохраняя LAN AP. Другие пользовательские STA-интерфейсы не удаляются.

Перенос WAN предусмотрен для **простой DSA-конфигурации** с `network.wan.device`, обычным `br-lan`, минимум двумя LAN-портами и уже настроенной masqueraded WAN firewall-зоной с входящей политикой DROP/REJECT. Новый порт удаляется из LAN-моста; `wan` и прямое указание порта в `wan6` обновляются. Старый WAN не превращается автоматически в LAN. Переставьте кабель провайдера в выбранный порт и проверьте доступ до `owp confirm`.

VLAN, tagged WAN, bridge-VLAN, старый `swconfig`, нестандартные мосты и сложный WAN6 отклоняются. Это требует адаптации по модели. Определение DSA намеренно консервативное и может отказать на поддерживаемом устройстве. Первый запуск на реальном роутере обязателен перед использованием на основной сети.

PPPoE изменяет существующий `wan`, сохраняя его физический порт и firewall-привязку; ручное создание зон не нужно. Требуются `ppp`, `ppp-mod-pppoe` и корректная существующая WAN-зона. Провайдерский VLAN, MTU, нестандартный IPv6 и дополнительные сети настраиваются отдельно. Новые произвольные гостевые сети и VLAN скрипт не создаёт.

## Интернет через Wi-Fi / повторитель (0.2.0)

Это **IPv4 AP+STA с NAT и отдельной подсетью**, а не IEEE 802.11s mesh или прозрачный мост. Основной роутер может оставаться обычной точкой доступа. Поддержка AP+STA зависит от драйвера и проверяется только на устройстве.

1. Подключитесь к локальной Wi-Fi сети второго роутера или к его LAN-порту. Сохраните проводной доступ для восстановления.
2. Запустите `owp repeater` или меню **7 → 4**. Выберите радиомодуль (`radio0` на типичной однодиапазонной модели).
3. Мастер сканирует сети и показывает SSID/BSSID, канал, сигнал. Выберите номер и введите пароль скрыто. Поддерживаются видимые WPA2/WPA3 Personal сети с паролем 8–63 печатных ASCII-символа. Открытые, WEP, WPA1, enterprise и скрытые сети в этом мастере не поддерживаются.
4. Оставьте текущий LAN IP или задайте новый, например `192.168.50.1`. При смене LAN мастер создаёт `/24` и DHCP-пул `.100`–`.199`; адрес роутера должен быть вне пула. Существующие DHCP-резервации и специальные DHCP-опции требуют предварительного переноса в LuCI, иначе смена LAN отклоняется.
5. Подтвердите `Yes`. Создаются `owp_wwan` (DHCP), `owp_sta`, отдельная WAN-подобная firewall-зона и разрешение LAN → uplink. SSID и пароль вашей локальной AP сохраняются. Не переименовывайте её в SSID основной сети в ожидании бесшовного роуминга: здесь разные IP-подсети.
6. Скрипт ждёт DHCP до примерно 40 секунд после reload. Реальная полученная подсеть сравнивается со всеми IPv4-адресами остальных настроенных интерфейсов, включая вторые адреса и маски шире `/24`. При пересечении или отсутствии адреса настройки автоматически откатываются. Причина доступна в `owp repeater-status` и главном меню. Повторно запустите мастер, выберите другой LAN IP и подтвердите. Первый конфликт обнаруживается **после подключения**, поскольку Wi-Fi сканирование не сообщает IP-подсеть основной сети.
7. После успешной проверки откройте интернет на телефоне, затем `owp confirm` → `Yes` до истечения общих 120 секунд. До окончания проверки повторителя сохранение заблокировано. Полученный DHCP-адрес сам по себе не доказывает доступность интернета.

При смене LAN IP переподключите телефон с автоматическим получением адреса (DHCP). SSH и LuCI будут доступны по **новому локальному адресу второго роутера**. Если на телефоне статический адрес, вручную укажите адрес из новой подсети, например `192.168.50.10/24`, шлюз/DNS `192.168.50.1`.

Необходимы действующая защищённая AP в доверенной LAN-зоне, статическая LAN с работающим DHCP и `rpcd-mod-iwinfo` для сканирования. Мастер не перезаписывает чужие объекты с зарезервированными именами. Загрузка/установка пакетов автоматически не выполняется. В стандартном образе с LuCI компонент `rpcd-mod-iwinfo` обычно уже присутствует.

Проводной WAN не выключается при создании повторителя. У `owp_wwan` метрика 500, поэтому проводной WAN с обычной меньшей метрикой имеет приоритет. Для проверки беспроводного uplink отсоедините кабель **WAN**, сохраняя управляющий кабель **LAN**. При собственных policy routes/RouteWolf маршруты проверяются отдельно — мастер их не переписывает.

На одном радио AP и STA делят канал и эфир: скорость ниже, чем при отдельном радио/проводном uplink, и не может гарантированно достигать паспортной скорости. Потеря основной AP или изменение её канала может сделать недоступной и локальную AP. Постоянного watchdog/reconnect-демона нет; автоматическое переподключение выполняет штатный Wi-Fi стек, застрявший драйвер мастер не восстанавливает. Для выбора другой основной AP запустите мастер снова. BSSID и канал выбранной сети закрепляются; роуминга между несколькими основными AP нет. Прозрачный L2-мост, WDS, 802.11s, общий DHCP и бесшовный роуминг не реализованы. IPv6 uplink не настраивается.

## Ограничения и хранение данных

- Целевые прошивки: официальные OpenWrt 24.10/25.12, но **на реальном оборудовании эта версия ещё не проверена**. Форки могут менять ubus, имена пакетов и структуру сети. Компоненты должны присутствовать в прошивке.
- Пароли вводятся скрыто. Они, как и штатный UCI, хранятся в конфигурациях и резервных копиях в открытом виде, доступном root. Не публикуйте `/etc/owrt-pocket` и `/etc/config`.
- До 20 подготовленных транзакций хранятся в `/etc/owrt-pocket/transactions`; затем новые изменения блокируются, пока владелец не архивирует/удалит старые каталоги. Не удаляйте ожидающую транзакцию. Установленные пакеты и записи языка занимают flash.
- Логи команд могут содержать IP/MAC и имена устройств. Встроенной телеметрии нет; диагностика отправляет ICMP на `1.1.1.1` и `9.9.9.9`, DNS-запрос `openwrt.org`; установка пакетов обращается к настроенным feeds.
- Скрипт не переименовывает root: это затрагивает UID, SSH, пути и совместимость OpenWrt. Для смены имени устройства используйте LuCI; управление отдельными SSH-пользователями в эту версию не включено.
- Отсутствие ICMP-ответа не доказывает отсутствие интернета. Нет автоматического «исправления всего», удаления VPN, сброса firewall, прошивки или перезагрузки без отдельной разработки.
- Подробные выводы адресов, клиентов и пакетов прокручиваются в терминале. Это текстовый интерфейс, а не полноэкранный web-UI.

## Проверки и испытание

```sh
shellcheck -S warning -s sh src/owp install.sh
busybox ash -n src/owp
python3 -m unittest discover -s tests -v
```

Тесты проверяют shell-функции транзакций и сетевые проверки с временными файлами и подменёнными сетевыми командами. В GitHub Actions дополнительно собираются закреплённые версии upstream UCI/libubox/jsonfilter и проверяется настоящее UCI staging, сохранение SSID с кавычками и JSON-пути сканирования. Это не проверяет драйверы, реальный netifd, firewall или радио. План испытаний: [TESTING.md](TESTING.md).

Основания для реализации: [UCI networking](https://openwrt.org/docs/guide-user/network/uci), [DSA](https://openwrt.org/docs/guide-user/network/dsa/dsa-mini-tutorial), [wifi CLI](https://github.com/openwrt/openwrt/blob/main/package/network/config/wifi-scripts/files/sbin/wifi), [hostapd ubus](https://github.com/openwrt/openwrt/blob/main/package/network/services/hostapd/src/src/ap/ubus.c), [apk в OpenWrt](https://openwrt.org/docs/guide-user/additional-software/apk). Код `wifi` и hostapd сверялся с upstream; часть Wiki закрыта защитой от автоматического просмотра. Наличие документации не заменяет проверку конкретной модели.
